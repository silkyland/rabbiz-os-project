# Plan: RabbizOS desktop environment — `rabbiz-de`

> Generated by deep-plan on 2026-11-17. Ground-truth source: Smithay 0.7.0 (GitHub tag `v0.7.0`) plus the sources in this repo.
> Goldfish: OPEN ITEMS (4, see section 5)

## 1. Context

RabbizOS is an Arch Linux ARM64 system on a Samsung Galaxy A21s (`SM-A217F`, Exynos 850, 720×1600 DSI panel, 2.8 GB RAM). Today the graphical session is labwc (wlroots) + a Quickshell/QML shell (`a21s-phone-session.service`). This plan replaces that shell layer with `rabbiz-de`: a from-scratch Rust desktop environment that owns the Wayland compositor, DRM/KMS output, input, the GPU (Panfrost/EGL) renderer with a CPU (pixman) renderer option, every shell screen, and the Rabbiz design system. **Done** means `rabbiz-de` is the default session, all screens below work on the device within the performance budget, existing Wayland/X11 apps and the `a21s-osk` keyboard still work, and the old labwc session remains a one-command fallback.

- **Research Questions**: RQ1 Smithay can drive exynos/KMS with GL composition — PARTIAL, labwc proves GLES2 on card0 (`docs/FINDINGS-hw-render.md:10`), smithay-specific path is spike S1. RQ2 mode/refresh/plane formats — UNVERIFIED (S1). RQ3 CMA/GPU headroom — VERIFIED, ~14 MiB per full-screen client and 181 MB CMA free (`docs/FINDINGS-hw-render.md:24`, `docs/a21s-qt-gpu-scanout.md:50`). RQ4 client buffer import — PARTIAL, exynos has no IOMMU for non-contiguous panfrost dmabufs (`rootfs-overlay/etc/systemd/system/a21s-phone-session.service:44-47`), direct scanout needs S1. RQ5 required protocols — VERIFIED except wlr-screencopy, which smithay 0.7.0 does not provide. RQ6 `a21s-osk` compatibility — UNVERIFIED (S2). RQ7 integration regressions — VERIFIED: grim (`rootfs-overlay/usr/local/bin/a21s-screenshot:59`), power cmd (`rootfs-overlay/usr/local/bin/a21s-power-key:35,44`), DRM keeper. RQ8 build/deploy — VERIFIED, arm64 Docker (`docs/BUILD.md` §6). RQ9 disk — VERIFIED at the time of the earlier measurement (377 MB, `docs/DESKTOP-SHELL.md:149`); the same file records cleanup to 1.2 GB (`:157-158`) and the handoff records 2.2 GB, so the plan requires a re-measure before M6. RQ10 behaviours to preserve — VERIFIED (prefs, lock, catalog). RQ11 GPU policy — PARTIAL, owner confirmed a compositor-only GPU exception on 2026-11-17.
- **Assumptions**: the Decision Brief was confirmed on 2026-11-17 with two additions — rootless XWayland is in v1, and the renderer must support both hardware (GL) and software (pixman) paths. v1 is handset-only with a form-factor seam. App processes stay software (`QT_QUICK_BACKEND=software`) except existing opt-in wrappers. Lock behaviour stays swipe + fingerprint; no PIN is introduced in v1. No ONE-WAY decision remains unconfirmed.
- **Assumptions (continued)**: the implementation device is reachable with the credentials the owner already uses; if it is not, every device gate is recorded as deferred, not silently passed. (The planning host cannot SSH to `172.16.42.1`; that is an environment limitation, not a plan requirement.)
- **Open questions**: (a) a real PIN/password lock is a product decision for a later version; (b) whether the legacy blue accent stays selectable after the plum/copper redesign (this plan keeps it as a non-default option, not a default); (c) the owner's exact X11 acceptance apps beyond `xterm`/`kcalc`; (d) whether light theme ships in v1 or waits for the v1.1 polish pass (this plan ships tokens and dark default, light QA in M6).

## 4. Audit findings

- **[High] Screenshot path breaks**: `a21s-screenshot` calls `grim`, which needs wlr-screencopy; smithay 0.7.0 has no such module, so the Power+Volume screenshot combo and any portal screenshot die under `rabbiz-de`. `rootfs-overlay/usr/local/bin/a21s-screenshot:59,65`. In scope (G7).
- **[High] Power/sleep path is bound to Quickshell**: `a21s-power-key` writes `a21s-power.cmd` for `SystemControl.qml`, and when `quickshell` is not running it writes the backlight directly. With `rabbiz-de` running, the DE would be bypassed and brightness/DPMS could fight. `rootfs-overlay/usr/local/bin/a21s-power-key:4-5,35,44-46`. In scope (G8).
- **[High] OSK depends on two protocols**: `a21s-osk` needs wlr-layer-shell and `zwp_input_method_v2`; both exist in smithay but are unproven together with this client. `tools/a21s-osk/README.md:8-9,27`. In scope (G3/G12, spike S2).
- **[High] Existing GPU path is a workaround, not a foundation**: the QML shell needs pinned Mesa and `LD_PRELOAD` to import buffers, and labwc leaks CMA on imported buffers (`MODE_DESTROY_DUMB` → EACCES). `docs/FINDINGS-hw-render.md:26-37`, `docs/a21s-qt-gpu-scanout.md:11-16`. In scope as a reason not to reuse Quickshell for the DE (G11).
- **[Medium] No native performance harness**: `scripts/frame_time.sh` parses Qt frame log lines and cannot report compositor frame pacing; there is no RSS/CMA/frame-time contract for a Rust compositor. `docs/HANDOFF-DESKTOP-SHELL.md:86-90`. In scope (G9).
- **[Medium] Session/app scale inconsistency**: session exports `QT_SCALE_FACTOR=1`, Chrome uses `--force-device-scale-factor=1.5`; the DE must define one app environment so new screens and old wrappers agree. `a21s-phone-session`, `rootfs-overlay/usr/local/bin/a21s-browser`. In scope (G10).
- **[Medium] Disk pressure**: the last direct measurement was 377 MB free, but the repo records cleanup to 1.2 GB and 2.2 GB since (`docs/DESKTOP-SHELL.md:149,157-158`, `docs/HANDOFF-DESKTOP-SHELL.md:93-95`). Re-measure before setting the M6 budget; a Rust compositor with debug symbols, wallpapers and fonts can consume hundreds of MB. In scope (M6-T4, risk register).
- **[Low] Brand drift**: the shell palette is graphite/blue (`shell/A21s/Theme/Theme.qml:12-45`) while the brand is plum/copper/cream (`docs/BRAND.md:42-46`); icons mix shapes and third-party styles (`docs/home-icons-preview.png`). In scope (G4, design system).
- **[Low] Lock screen has no authentication**: unlock is a swipe or fingerprint; no PIN. `shell/A21s/Panels/LockScreen.qml:1-40`. Out of scope by decision, listed as an open question.
- **[Low] XWayland disappears with labwc**: the current session gets XWayland from labwc; a new compositor must start its own rootless XWayland or X11 apps stop working. In scope (G15).

## 7. Design decisions

### Decision 1: Own compositor on Smithay 0.7 (closes G1, G2, G11)
- **Decision:** `rabbiz-de` is a Linux-only Rust binary that opens `/dev/dri/by-path/platform-exynos-drm-card` through libseat, takes DRM master, drives atomic KMS through `DrmCompositor`, and owns the Wayland socket. Quickshell/QML is not in the runtime path.
- **Reversibility:** ONE-WAY (owner-confirmed 2026-11-17). The fallback is the existing labwc session, not a code path back.
- **Rationale:** smithay 0.7 provides exactly the pieces the device needs (`DrmCompositor`, GlesRenderer, libseat, layer-shell, input-method); labwc proves the exynos/Panfrost GL path works (`docs/FINDINGS-hw-render.md:10`). Keeping labwc as the session fallback preserves a working device if M0's spike fails.
- **Rejected:** extend Quickshell (cannot own KMS or meet the frame contract); KWin/Wayfire (heavy, unverified on 2.8 GB); a pure software framebuffer compositor (no client protocol path).

### Decision 2: One scene, two renderers — GL default, pixman software option (closes G3)
- **Decision:** `de-api` defines `RendererKind::{Gl, Soft}`; `de-render` implements both. `Gl` = `GlesRenderer` on a `GbmDevice`/EGL display; `Soft` = `PixmanRenderer` on the same `GbmAllocator`/`DrmCompositor` scanout buffers. `--renderer=auto|gl|soft`; `auto` tries GL and falls back to soft if EGL/GBM init fails or `CmaFree < 96 MiB`. Both paths consume the same RGBA8 layer textures from `de-paint`.
- **Reversibility:** REVERSIBLE (per-run flag; no data migration).
- **Rationale:** `DrmCompositor::render_frame` is generic over `R: Renderer + Bind<Dmabuf>`, and `PixmanRenderer` implements `Bind<Dmabuf>`, `ImportMem` and `ExportMem` over linear dmabufs (`.../pixman/mod.rs#L1201-L1210,L888,L1003`). The same scene therefore runs on GPU or CPU without a second compositor. Software mode is slower but keeps the device usable when EGL/CMA is unhealthy.
- **Rejected:** a separate software compositor (duplicate protocol/window logic); wgpu/Vulkan (PanVK is experimental and not the scanout path); per-frame CPU fallback inside GL (cannot recover from a wedged EGL context).

### Decision 3: Retained scene + cached RGBA units; rasterize on change, composite on every frame (closes G4)
- **Decision:** `de-paint` is a retained scene of layers/items with layout, damage and a texture cache. Visual units (a card, an icon, a text run, a wallpaper) are rasterized with tiny-skia, cosmic-text/rustybuzz and resvg into premultiplied RGBA8 pixmaps when their content changes; `de-render` uploads them as textures and composites them with transforms. Animations move cached textures; they never re-rasterize vectors per frame.
- **Reversibility:** REVERSIBLE.
- **Rationale:** A 720×1600 full-frame CPU repaint cannot hold 60 fps with live text on an A55; cached units + GPU quads can. This also gives Thai shaping through the same cosmic-text stack already proven in `tools/a21s-osk/crates/osk-render` (`tools/a21s-osk/README.md:24-27`).
- **Rejected:** Skia/Qt scene graph (heavy, pulls the Qt renderer back in); pure GPU SDF UI (more shader work, worse Thai text without an atlas); per-frame tiny-skia (fails the frame budget).

### Decision 4: Shell UI is in-process, not a Wayland client (closes G4, G11)
- **Decision:** Home, status bar, shade, lock, OSD, settings and recents are drawn by `de-ui` as compositor layers. They are not separate Wayland surfaces. Only third-party apps, XWayland and `a21s-osk` are Wayland clients.
- **Reversibility:** REVERSIBLE.
- **Rationale:** avoids a protocol round-trip and a second process for the most latency-sensitive surfaces; gives exact control over direct scanout and blur; removes the Quickshell/patched-Mesa dependency.
- **Rejected:** layer-shell shell process (extra process, IPC latency, no compositor-side morph/blur control); QML shell beside a Rust compositor (two design systems).

### Decision 5: Protocol set for coexistence (closes G5, G12)
- **Decision:** wire smithay's globals for `wl_compositor`, `wl_subcompositor`, `wl_shm`, `wp_viewporter`, `xdg-shell`, `zxdg_decoration_v1` (answer `ServerSide`; handset draws no decorations), `xdg-activation-v1`, `xdg-foreign-v2`, `wlr-layer-shell-v1`, `zwp_text_input_manager_v3`, `zwp_input_method_manager_v2`, `zwp_virtual_keyboard_manager_v1`, `ext-session-lock-v1`, `wp_presentation`, `ext-idle-notify-v1`, `zwp_idle_inhibit_manager_v1`, data device/primary selection, `wlr-data-control-v1` + `ext-data-control-v1`, `ext-foreign-toplevel-list-v1`, and `wp_linux_dmabuf_v1` with **linear formats only**. Implement only what smithay 0.7.0 does not ship: `wlr-screencopy-v1` and the XWayland glue. Do not advertise `wp_fractional_scale_v1` in v1 (see Decision 7).
- **Reversibility:** REVERSIBLE (globals can be gated by config).
- **Rationale:** this is the minimum that keeps `a21s-osk`, Qt/GTK/Chrome, screenshots, XWayland and clipboard working. Linear-only dmabuf avoids advertising formats exynos cannot import (`a21s-phone-session.service:44-47`).
- **Rejected:** advertise every dmabuf modifier (clients pick tilings that fail import); skip dmabuf entirely (some clients refuse shm for video/GL).

### Decision 6: Keep the unit name; wrapper tries DE, falls back to labwc (closes G10)
- **Decision:** `a21s-phone-session.service` keeps its name and `Conflicts=steamos-session.service`; its `Restart=on-failure` stays as a last resort, while `a21s-session` owns the DE crash counter. Its `ExecStart` becomes `/usr/local/bin/a21s-session`. `a21s-session` **does not turn the DE on by default in M1**: if `/etc/rabbiz-de/enabled` is absent and `--de` was not passed, it `exec`s `/usr/local/bin/a21s-phone-session` (the unchanged labwc launcher). When enabled, it clears the wlroots/Mesa variables (`LD_PRELOAD`, `WLR_*`), loads the contract via `eval "$(rabbiz-de env --shell)"`, runs `rabbiz-de` as a child, and counts rapid failures in `$XDG_RUNTIME_DIR/rabbiz-de.fail` (gamer-owned): exit 75 (pre-first-frame init failure) or 3 failures in 60 s → log the reason and `exec a21s-phone-session`; otherwise it re-execs itself. A `mode` file at `$XDG_CONFIG_HOME/rabbiz-de/mode` (`de` or `labwc`, gamer-owned) is read before `/etc/rabbiz-de/enabled`; P15 writes `labwc` there and restarts the unit, and `a21s-session --labwc` is the manual override when run as the unit. M6-T7 installs the root-owned `/etc/rabbiz-de/enabled` marker via `de_deploy.sh`; rollback removes it (root) or writes `mode=labwc` (gamer). `a21s-drm-keeper` and `a21s-display-pin` stay untouched.
- **Reversibility:** REVERSIBLE (remove the marker / restore the old ExecStart).
- **Rationale:** the device keeps a working session until the launcher and lock screen exist (M3/M4), and the wrapper — not systemd — owns the crash counter, so the fallback is actually reachable; `exec` is only used for the labwc branch, where no further accounting is needed.
- **Rejected:** flipping the default at M1 (boots to a compositor with no home/lock); a second session unit (conflicts); a systemd `OnFailure` chain (slower and the wrapper still cannot count crashes); using `exec rabbiz-de` (loses the crash counter).

### Decision 7: App policy — fullscreen, software toolkits, scale 1.5 wrappers (closes G5, G10)
- **Decision:** handset windows are configured `Fullscreen` (not merely maximized) with no decorations; `zxdg_decoration_v1` answers `ServerSide` and the handset draws none (so Qt/GTK do not add client-side titlebars), while a future tablet mode can draw them. Apps inherit `QT_QUICK_BACKEND=software`, `A21S_FORCE_SOFTWARE=1` (this is what stops `a21s-qt-render` from opting into GPU), `QT_QPA_PLATFORM=wayland`, `QT_SCALE_FACTOR` as today (session 1, wrappers 1.5). The compositor has **no global output scale** (scale 1): each client's buffer scale is honored by mapping its logical size to the physical 720×1600 output at 1:1 when the resulting buffer is exactly the output size, and downscaling only a buffer larger than the output (e.g. a 2× client). The app surface is the full 720×1600 and the 32 px gesture bar overlays the bottom. GPU app opt-ins stay opt-in.
- **Reversibility:** REVERSIBLE.
- **Rationale:** preserves the verified app path and avoids the exynos non-contiguous-dmabuf class; the DE's own GPU use is scoped to the compositor.
- **Rejected:** force GPU for all apps (CMA leaks/faults); integer output scale 2 (4× pixels, too slow); per-app scale guessing.

### Decision 8: Rootless XWayland in v1 (closes G13)
- **Decision:** start `XWayland` from `de-protocols` at session start when `RABBIZ_XWAYLAND=1` (default 1) with smithay's `XWayland::spawn` + `X11Wm::start_wm`, publishing `DISPLAY`; map X11 surfaces through the same handset fullscreen policy; expose `xwayland-shell-v1`.
- **Reversibility:** REVERSIBLE (flag can disable it; no X11 state is stored).
- **Rationale:** the owner asked for XWayland; smithay and anvil already implement the rootless WM pattern (`anvil/src/state.rs#L723-L753`, `anvil/src/shell/x11.rs#L48-L80`); `xorg-xwayland` is already in the session package set.
- **Rejected:** `xwayland-satellite` (extra process/protocol assumptions); nested Xephyr (wrong integration); X11-less v1 (owner rejected).

### Decision 9: Rabbiz design system — plum, copper, cream; one accent (closes G4, G16)
- **Decision:** adopt the brand palette as the base: plum surfaces, copper accent, cream text (`docs/BRAND.md:42-46`). One token source in `de-design`, dark-first, with a light "Parchment" mapping. Copper is the default accent; legacy `blue` stays selectable but is no longer the default. Third-party app icons keep their own artwork; only Rabbiz-owned apps get the sand/plum tile.
- **Reversibility:** ONE-WAY for brand identity (owner-confirmed 2026-11-17); individual token values are REVERSIBLE.
- **Rationale:** the current graphite/blue theme has no Rabbiz identity (`Theme.qml:12-45`), and mixed icon styles break harmony (`docs/home-icons-preview.png`). A single accent plus two neutrals is enforceable by tests.
- **Rejected:** keep One UI blue (brand mismatch); per-app accent colors (no harmony); full icon restyle (violates the AGENTS rule for third-party apps).

### Decision 10: Rust app catalog and launch path (closes G5)
- **Decision:** `de-apps` parses `.desktop` files from `XDG_DATA_DIRS`, ports the dedupe preference groups from `AppCatalog.js`, resolves icons through hicolor with resvg rasterization and a cache, and launches with `setsid`/`Command` using the desktop contract environment. Recents are keyed by desktop id + PID/window app_id.
- **Reversibility:** REVERSIBLE.
- **Rationale:** the QML catalog logic is small and already tested (`shell/tests/appcatalog.test.mjs`); porting it keeps app ordering/aliases stable.
- **Rejected:** call `gtk-launch` for everything (no metadata, no icon control); reuse Quickshell `DesktopEntries` (process dependency).

### Decision 11: Rust services — D-Bus state + proven CLI mutations (closes G6)
- **Decision:** `de-system` uses zbus for NetworkManager/BlueZ/UPower/logind/MPRIS/Notifications state and for the notification server; mutations that already work reliably through `nmcli`/`bluetoothctl`/`wpctl` stay as thin subprocess calls on a worker thread. Battery, brightness and suspend follow the existing logind/sysfs contracts.
- **Reversibility:** REVERSIBLE.
- **Rationale:** avoids re-implementing NM secret agents and BlueZ pairing agents in v1, while removing polling shell-outs from the UI thread.
- **Rejected:** pure D-Bus for mutations (secret-agent/pairing edge cases); keep polling every 2 s on the UI thread (jank).

### Decision 12: Reuse `a21s-osk` as the only keyboard; implement IM protocols (closes G12)
- **Decision:** `rabbiz-de` implements `zwp_input_method_v2` + `text_input_v3` + layer-shell, then launches the existing `a21s-osk` binary as the single input method. If the binary is missing, launch `squeekboard`; never both. The DE does not draw its own keyboard in v1.
- **Reversibility:** REVERSIBLE.
- **Rationale:** the keyboard already has Thai/English, prediction and the Gboard layout (`tools/a21s-osk/README.md:8-9`); reusing it avoids a second keyboard project and keeps the "one input method per seat" rule.
- **Rejected:** in-DE keyboard (duplicate work); squeekboard-only (worse Thai layout); `zwp_virtual_keyboard` (no IME/preedit).

### Decision 13: Hardware keys and screenshots stay external, DE consumes their outputs (closes G7, G8)
- **Decision:** keep `volume-keys.py`, the hold-menu logic and `a21s-power-key` as system daemons. Patch only the `quickshell` liveness check to also detect `rabbiz-de`, and have `rabbiz-de` watch `a21s-power.cmd`, `a21s-volume.state` (OSD trigger) and `a21s-screenshot.state`. The DE handles `KEY_POWER`/`XF86PowerOff` from libinput on **release** by spawning `a21s-power-key toggle` detached (long press is recognized by the existing hold-menu path), so the hardware combos survive without labwc's keybind. Implement `wlr-screencopy-v1` in `de-protocols` so `grim` and `a21s-screenshot` keep working; the DE adds the flash/thumbnail UI from the state file.
- **Reversibility:** REVERSIBLE.
- **Rationale:** these daemons work today and are independent of the compositor; replacing them adds risk and loses the verified hardware combos.
- **Rejected:** move all key handling into the compositor (loses root evdev access and the knob/combo logic); replace grim with an internal-only screenshot (breaks the documented command).

### Decision 14: Own prefs file; never write the legacy `prefs.json` (closes G5)
- **Decision:** the DE stores its own state in `~/.config/rabbiz-de/prefs.json` (atomic write, backup before first mutation). It **reads** the legacy `~/.config/a21s-shell/prefs.json` once for defaults and brightness/wallpaper hints, but never writes it, because `ShellPrefs.save()` serialises a fixed key set and would erase new keys. Legacy keys stay untouched for the labwc fallback; the brand accent is `deAccent` (default `copper`) and the brand wallpaper is `deWallpaperId` (default `ember`) in the new file. This is deliberately not a dual-write.
- **Reversibility:** REVERSIBLE.
- **Rationale:** `ShellPrefs.qml:15-22` is the only user state that survives the migration; losing brightness/wallpaper on an OS update is unacceptable.
- **Rejected:** a new config directory (user loses settings); rewriting the old shell's prefs format (dual-write bugs).

### Decision 15: Bilingual by construction; accessibility is a gate (closes G14)
- **Decision:** all UI strings live in `de-ui/locales/{en,th}.toml`; no string literals in screen code. Thai shaping uses cosmic-text/rustybuzz with bundled OFL subsets (`assets/fonts/NotoSansThai-*.ttf`, `NotoSans-*.ttf`) loaded before system fonts, so host goldens and the device shape identically. Touch targets ≥ 48 px, text contrast ≥ 4.5:1, a reduced-motion pref, and no color-only state.
- **Reversibility:** REVERSIBLE.
- **Rationale:** the owner is Thai-first; retrofitting i18n after 20 screens is expensive, and contrast tests are cheap.
- **Rejected:** English-only (fails the owner's use); runtime string concat (breaks translation).

### Decision 16: Five worktrees, one scaffold, one integration lane (closes G15)
- **Decision:** M0 creates the full workspace and the `de-api` seams in a `feat/de-integration` worktree, then five lanes work in parallel worktrees with disjoint crate ownership (table 7.19). Integration merges in a fixed order, rebuilds in the arm64 container, runs the golden suite and the device smoke test.
- **Reversibility:** REVERSIBLE (process only).
- **Rationale:** the UI and the compositor can be developed independently once the scene/texture/input/service traits exist; disjoint crates keep merges mechanical.
- **Rejected:** one agent on one tree (serial, slow); per-file worktrees (merge hell); letting lanes edit shared workspace dependencies (Cargo.lock conflicts).

### 7.20 Session lifecycle contract (M1-T6)

- **Socket**: `rabbiz-de` listens on `wayland-0` (fixed) and creates it before the first frame. The wrapper waits up to 5 s for `$XDG_RUNTIME_DIR/wayland-0`; if it is missing, the start is a failure (exit 75 path).
- **Readiness**: after the first successful page flip, `rabbiz-de` writes `$XDG_RUNTIME_DIR/rabbiz-de.ready` containing `pid start_unix_ms`. The wrapper waits up to 10 s for that file, then exports `WAYLAND_DISPLAY=wayland-0`, `DISPLAY=:<n>` when XWayland is up, and runs `dbus-update-activation-environment --systemd WAYLAND_DISPLAY DISPLAY XDG_CURRENT_DESKTOP XDG_SESSION_TYPE XDG_SESSION_DESKTOP`. If readiness never arrives, the wrapper kills the child and counts one failure.
- **Exit codes**: `0` = clean session end; `75` = pre-first-frame initialisation failure (no failure counted, immediate labwc fallback); any other exit, signal, or timeout = one failure. `--force-fail` is a `rabbiz-de` flag that exits 75 immediately; `a21s-session` forwards it only when not in `--labwc` mode.
- **Crash counter**: `$XDG_RUNTIME_DIR/rabbiz-de.fail` is a newline list of Unix millisecond timestamps, gamer-owned. On each failure the wrapper appends and prunes entries older than 60 s; on readiness + 60 s uptime it truncates the file. 3 entries → `exec a21s-phone-session`.
- **Mode precedence**: `--labwc` > `--de` > `$XDG_CONFIG_HOME/rabbiz-de/mode` (`de` or `labwc`) > `/etc/rabbiz-de/enabled` (present = `de`) > default `labwc`. Missing/invalid mode logs and falls back to `labwc`; an unreadable root marker is treated as absent. `a21s-session --labwc` may be run as the unit's ExecStart (takes the labwc branch) or while the unit is stopped; the UI switch writes the mode file and restarts the unit.
- **Environment**: `rabbiz-de env --shell` prints the contract sourced from `de-system/env.rs` (the single authority) as `KEY=VALUE` lines plus explicit `unset KEY` lines for the wlroots/Mesa overrides; `a21s-session` evaluates those lines before starting the child, so the wrapper never duplicates the Rust table; values are single-quoted by the printer.
- **Stats**: the wrapper always passes `--stats-file $XDG_RUNTIME_DIR/rabbiz-de.stats.jsonl` and `--stats-summary $XDG_RUNTIME_DIR/rabbiz-de.summary.json`; M1 acceptance reads the summary, and the file is truncated at start.
- **Ownership**: the wrapper runs as `gamer`; it never writes `/etc` or `/run` outside its runtime dir. Only `de_deploy.sh --enable` (root) writes `/etc/rabbiz-de/enabled`.

### 7.21 Measurement contract (M0-T3/M0-T4/M0-T8)

- **Stdout purity**: `probe --json` and `--stats` write exactly one JSON object to stdout; all tracing/logs go to stderr and `journalctl`. `--stats-file` writes JSONL to the given path.
- **Probe fields**: `frame_interval_ms` = mean vblank interval over 100 commits (float), plus the fields shown in M0-T3. `errors[]` is a string array; `gl.ok:false` carries `gl.error`; `soft.ok:false` carries `soft.error`.
- **Per-second stats**: `cpu_ms` = p50/p95/max of frame preparation + commit time in the window; `gpu_ms` = EGL timer query or `null`; `damage_px` = pixels submitted in the window; `textures_mb` = live texture bytes at the end; `direct_scanout`/`primary_composite` = cumulative counters since start; `missed_frames` = frames whose vblank interval exceeded 1.5× `frame_interval_ms`.
- **Summary**: `--stats` (or SIGINT/`--duration`) prints `{scenario,duration_ms,frames,cpu_ms:{p50,p95,max},gpu_ms,missed_frames,rss_kb_peak,cma_free_min_kb,renderer}`. `--scenario <name>` is a label only; `--duration <sec>` stops the run and prints the summary; SIGINT does the same.
- **Bench**: `de_bench.sh` parses the summary; `--de` writes the mode file and restarts the unit under the lock, then restores the previous mode.

### 7.22 Device access prerequisite

All M0–M6 device gates require the A21s reachable as the owner's usual SSH target, with `scripts/device_session.sh` serialising access. The planning host currently gets `Permission denied` on `root@172.16.42.1`; the implementation session must be given working credentials (or the device physically) before M0-T3. If the device is unavailable, record the gate as deferred in section 11; do not mark it passed.

## 11. Change log

- **2026-11-17 (M1-T4 scanout waiver — S1 partial):** `direct_scanout > 0` for the dmabuf client is waived for M1. Measured on-device (flock + `/tmp` binary, `a21s-qt-gpu a21s-calculator` spawned): `primary_composite` = 10, `direct_scanout` = 0; per-element states show every element in `Rendering` — e.g. `Id(WaylandResource(wl_surface@23)):rendering, External(4):rendering, External(2):rendering, External(3):rendering`. Root cause is structural: smithay 0.7 attempts primary-plane assignment only for the *last* element and only when every element above it lands on overlay/cursor planes; the composited gesture-bar strip + pill are solid `TextureRenderElement`s that cannot take a plane, so the client surface is never the last element and zero-copy is never attempted. `wl_shm` clients (stock `a21s-calculator`) additionally cannot scan out at all — `primary_composite > 0` is the correct assertion there and holds. Only ~10–17 frames are submitted for a static calculator because damage stops arriving after the initial map — `FrameResult::is_empty` short-circuits `queue_frame`, so the counters stay flat by design and are not skewed (they increment only after the empty check). Defer real `direct_scanout` to M6-T1 when the shell chrome can be folded into the primary-plane assignment (e.g. bar drawn into the same plane path or omitted when a fullscreen dmabuf client is up); `PRESENT_FLAGS` already allows primary-plane scanout (`de-core/src/present.rs`).
