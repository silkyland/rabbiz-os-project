# `rabbiz-osk` — the RabbizOS on-screen keyboard

(Formerly `a21s-osk`; renamed 2026-11-18.)

Gboard-like on-screen keyboard for the A21s, written in Rust, replacing squeekboard at
milestone K7. The plan, evidence and open questions live in
[docs/PLAN-keyboard.md](../../docs/PLAN-keyboard.md); this file only says what exists today
and how to run it.

**Status (2026-11-17): the default keyboard on the A21s.** `rabbiz-osk` runs as a layer-shell
surface and delivers text through `zwp_input_method_v2`: English + Thai, Gboard-style panel
(clipboard, suggestion slots with the word being typed, mic stub), Thai layouts matching Gboard (letters on the top row with
Arabic digit corner hints, Thai digits on the `๑๒๓` page), shift, grapheme backspace with hold-to-repeat, long-press alternates (Thai rare
letters), input-purpose layouts (email/URL/number pad), live theme file and `sm.puri.OSK0`
compatibility for the shell's tiles. squeekboard remains installed as the fallback;
`rabbiz-osk-switch start|stop|status` flips between them. The strip predicts (on-device learning, K6), the clipboard button opens the last selections
from `wl-paste --watch` (K5, memory only), and the emoji key opens a full panel with 9
categories, bilingual (EN/TH) search and recents (K4). Voice is the remaining gap, listed in
[docs/PLAN-keyboard.md](../../docs/PLAN-keyboard.md) §12.

## What exists

| Path | Contents |
|---|---|
| `crates/osk-core/` | layout model + key geometry + hit testing, shift/caps FSM, Thai-grapheme backspace, space-swipe, language cycle, double-space period, auto-capitalise, touch gesture recogniser (tap / long-press / repeat / swipe / multi-touch). No I/O, no Wayland, no font code. |
| `crates/osk-render/` | the scene painter: tiny-skia rounded keys + cosmic-text labels (rustybuzz shaping, swash glyphs) → RGBA pixmap or PNG. Same scene code the `wl_shm` surface will reuse. Text always goes through cosmic-text's `Buffer::draw`; hand-placing glyphs double-prints them. |
| `data/layouts/en-us.toml` | 5 layers (base, numbers, symbols, emoji), long-press alternates, Gboard row proportions. |
| `data/layouts/th-kedmanee.toml` | Kedmanee as deployed in the squeekboard YAML today, 6 rows, Thai numerals, tone-mark alternates. |
| `crates/osk-wayland/` | the real client: layer-shell surface, `zwp_input_method_v2` text delivery, touch → gestures → core, shm blit. Binary `rabbiz-osk`. |
| `tests/osk_test_client.py` | GTK4 client used to prove commits on the device (focus it, then type). |
| `tests/device_test.sh` | start/shoot/tap/stop helper for on-device runs (copied to `/tmp` on the phone). |
| `data/emoji.tsv`, `data/layouts/emoji.toml` | generated by `dict-build/build_emoji.py` from Unicode `emoji-test.txt` + CLDR (EN/TH names); 253 emoji, 9 groups |
| `data/fonts/MaterialIcons-Regular.ttf` | Google Material Icons (Apache-2.0, `LICENSE-MaterialIcons.txt`) embedded in the binary — shift/backspace/return/globe/emoji/clipboard/mic are drawn with it, no font package needed on the device. |
| `spikes/s2-render/` | the K0 render spike (layer-shell + tiny-skia + cosmic-text), excluded from the workspace. |

Design rules already enforced by tests: every row fills the surface width, keys never overlap
or leave the surface, an inset row mirrors its margins, the emoji panel is shorter than the
letter layers, and a malformed layout is a typed error rather than a panic.

## Run

```sh
cd tools/rabbiz-osk
cargo test                                   # host logic + renderer tests (no device)
cargo run -p osk-render --bin osk-preview    # writes build/osk/*.png (2x, dark/light/shift)
```

`osk-wayland` needs Linux (`libxkbcommon`) — build it in the arm64 Rust container, see
[docs/BUILD.md](../../docs/BUILD.md) §6, then `rabbiz-osk-switch start` on the phone.

`build/osk/` is gitignored; open `en-us-base-dark.png` and
`th-kedmanee-base-dark.png` to review a layout without touching the phone.

## Layout file format

`[geometry]` fixes the surface width, key height, gaps and the suggestion strip. `[keys.<name>]`
defines non-character keys (`shift`, `backspace`, `return`, `space`, `layer`, `language`);
a token in a row that is not a `[keys]` name is committed as text. `[[layer]]` holds string
rows plus a per-row `insets` list in letter-key units. Keys are normalised per row, so `width`
only shapes ratios — Gboard's half-key inset on the `asdf` row is `insets = [..., 0.5, ...]`.

## Not built yet

Backspace hold-to-repeat (gesture emits `Repeat`; the Wayland loop has no timer), long-press
alternates popup, the Thai shifted layer, emoji categories/search/recents, the suggestion strip
and predictor (`osk-predict`), clipboard history, `sm.puri.OSK0` D-Bus compatibility for the
Quick Settings tiles, the theme file from `Appearance`, and the `zwp_virtual_keyboard` fallback
for Chrome/XWayland fields. Details and evidence: [docs/PLAN-keyboard.md](../../docs/PLAN-keyboard.md) §12.
